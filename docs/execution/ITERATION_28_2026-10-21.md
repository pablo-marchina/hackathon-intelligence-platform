# Iteração 28 — XML grande com parsing incremental e orçamentos de segurança

**Base:** Iteração 27 (472 testes Python). **Data:** 21/10/2026. **Estado:** implementação validada localmente, **não** aprovada para produção.

## Objetivo

Aumentar a capacidade de descobrir URLs de eventos em RSS/Atom e sitemaps XML grandes, inclusive `.xml.gz`, preservando autorização por fonte e memória limitada durante o parsing. Não habilita novas fontes nem executa coletas externas.

## Entrega

- Listagens com até **2 MiB descomprimidos** continuam no caminho anterior, com parser XML protegido contra DTD/entidades.
- Acima de 2 MiB, um `XMLPullParser` recebe blocos de **32 KiB** de um `BytesIO` ou `gzip.GzipFile`, sem `ET.fromstring` do documento completo. Não se materializa uma lista de todos os itens nem o XML descomprimido completo.
- Novos orçamentos para esse caminho: **12 MiB** de XML descomprimido, no máximo **8 MiB** de entrada comprimida/não comprimida, profundidade máxima **32 níveis** e até **300.000 elementos**. O limite de bytes da camada HTTP continua independente e deve ser respeitado.
- A validação por `defusedxml` proíbe DTD e entidades **no próprio parser**, inclusive XML UTF-16; a busca adicional de marcadores ASCII trata também fragmentos separados entre os blocos lidos.
- Mesmo com documentos grandes, `listing_offset` conta entradas brutas (inclusive URLs descartadas), mantém as janelas de 2.500 URLs por listagem ou 250 sub-sitemaps e só registra `rel=next` após a última janela do documento.
- A política atual mantém apenas URLs dos hosts autorizados, sem credenciais embutidas e com esquema HTTP(S). A verificação de robots/DNS/TLS continua no fetcher.
- O buffer de eventos processados e nós XML irmãos é liberado incrementalmente para reduzir a memória de parsing. Limites de elementos e profundidade reduzem ataques com tags excessivas.
- O pacote Python declara a dependência de runtime `defusedxml>=0.7.1,<1.0`.

## Limitações e gates pendentes

1. A camada HTTP conserva o limite independente da resposta. Este parser não substitui streaming de *rede* nem suporta XML arbitrariamente grande; documentos acima de 12 MiB não são ingeridos neste checkpoint.
2. Documentos XML grandes são reprocessados desde o início a cada janela de cursor; uma evolução futura poderia fazer *spooling* controlado ou índices intermediários para reduzir custo de CPU quando muitos offsets são necessários.
3. A execução real com PostgreSQL, a migração + E2E com fontes autorizadas, Redis/Celery, o build Next.js e o CI remoto **não foram realizados aqui**.
4. O frontend não tem `package-lock.json`; `npm ci --offline` falha antes de instalar dependências. A geração do lockfile não concluiu por falta de resposta do registry; não foi incluído um lockfile artificial.
5. Nenhum novo hackathon real foi coletado ou confirmado. O número histórico de 250 do corpus W2 não equivale ao catálogo atual.
