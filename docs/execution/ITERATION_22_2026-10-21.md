# Iteração 22 — qualidade de catálogo, funil e cobertura por fonte

**Data:** 21/10/2026. **Base:** Iteração 21. **Estado:** implementada localmente; ainda não aprovada para produção.

## Objetivo

Tornar mensuráveis, a partir do PostgreSQL atual, os principais gargalos de crescimento de um catálogo mundial de hackathons: filas de descoberta, registros extraídos aguardando normalização e completude das informações utilizadas pelos filtros.

## Entregas

1. `/admin/coverage`, via `CoverageRepository.snapshot()`, preserva a contagem global de hackathons ativos, únicos e não mesclados. Novas contagens de source-event payloads distinguen registros staged, normalizados, aguardando normalização e com erro. **Registros de fonte não são eventos únicos.**
2. Estados da fila por fonte (`PENDING`, `RETRY`, `CLAIMED`, `DONE`, `EXHAUSTED`), URLs `ready_now` e claims expiradas são agregados sem multiplicação causada por `JOIN` com eventos. O total global é a soma de *tarefas de URL por fonte*, nunca a soma de hackathons atribuídos.
3. Percentuais de preenchimento para formato, URL e prazo de inscrição, custo, elegibilidade mundial, descrição, verificação recente, organizador, patrocinadores, tracks, tecnologias, premiações e regras de elegibilidade. Denominador = **hackathons únicos ativos**. Em catálogo vazio, retorna `null` (N/A), e não 0%.
4. Relatório CLI `scripts/catalog_coverage_report.py` em Markdown e JSON estendido. Dashboard `/admin` mostra as métricas e permite localizar fontes com fila esgotada; não expõe tokens nem altera políticas de permissão.
5. Exercício PostgreSQL descartável `scripts/ops/catalog_coverage_integration_check.py` ampliado com dados sintéticos em transação que é revertida, cobrindo registros de fonte, backlog, normalização e completude. O E2E RSS → backlog → normalização → busca também verifica o aumento de registros únicos e a diminuição do backlog de normalização. Ambos integrados ao CI já existente.

## Como usar depois de aplicar as migrações (PostgreSQL real)

```bash
python scripts/catalog_coverage_report.py --format markdown
python scripts/catalog_coverage_report.py --format json --recent-days 14
```

**Importante:** nenhum comando acima coleta eventos. Os números são consultas ao banco conectado. O relatório recusa substituir os dados ausentes pelo corpus histórico W2 de 250 eventos.

## Limitações

- Sem PostgreSQL ativo neste ambiente: SQL de relatório e exercícios integrados não foram executados contra um banco real, portanto os resultados de integração **não** estão aprovados.
- Sem build completo do Next.js; apenas checagem de sintaxe TSX para os arquivos editados.
- Sem nova coleta externa; **nenhuma expansão de catálogo comprovada nesta iteração**.
- Nenhuma fonte com status de permissão pendente foi ativada; nenhum envio de email foi disparado.
- Não atualiza automaticamente o repositório remoto no GitHub.
