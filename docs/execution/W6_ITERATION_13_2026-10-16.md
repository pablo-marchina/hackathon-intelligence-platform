# Hackathon Intelligence Platform — W6 / Iteração 13

Data: 2026-10-16. Base: Iteração 12 (293 testes). Estado: **implementação local, sem aprovação de produção**.

## Objetivo

Fechar uma lacuna funcional no fluxo busca salva → preferências → alerta → email: o envio exigia consentimento explícito, mas a interface não tinha controle de opt-in de email. Uma segunda falha permitia salvar JSON de filtros com erros de campo, versão ou tipo que seriam descartados silenciosamente pelo worker.

## Entrega de código

1. `GET /v1/me/alert-preferences` (requer sessão): devolve o estado efetivo `new_match` para `IN_APP` e `EMAIL`. `EMAIL` só está habilitado se houver email no cadastro e uma preferência afirmativa válida; uma negação específica tem precedência sobre um opt-in curinga. Reutiliza-se o `PUT /v1/me/alert-preferences` já existente com proteção CSRF e transação no PostgreSQL.
2. `/saved-searches` (Next.js): controles explícitos para alertas no aplicativo e para email (opt-in), buscando o estado real no backend após a alteração. Falhas de consulta desabilitam os controles, sem deduzir consentimento. Erros de rede são tratados; buscas salvas continuam disponíveis mesmo se a consulta das preferências falhar.
3. `SavedSearchCreate`: valida a versão do schema, nomes de filtros, tipos e valores da API, listas de enum e códigos de país. Proíbe opções de paginação/ordenação no monitor. Canonicaliza o JSON antes de persistir, normalizando códigos de país e removendo defaults não necessários. Busca vazia é válida e corresponde a todos os eventos posteriores ao momento relevante.
4. `/alerts`: novo componente `AlertInbox` para marcar alertas como lidos utilizando o endpoint PATCH existente, sessão e CSRF. Sem mudança no processamento das filas.
5. Testes: validação HTTP 401/422/200, consistência da preferência explícita, normalização, rejeição de filtros inválidos e contratos de segurança do frontend.

Nenhuma migração SQL nesta iteração. A revisão esperada continua `0009_w6_alert_match`. Celery Beat, matching e SMTP continuam **desativados por padrão**.

## Limites e próximos gates

- Novos testes HTTP usam overrides de dependências, **não** são prova de persistência PostgreSQL real nem de entrega SMTP.

- **Não habilitar schedulers ou email de produção antes dos testes integradores e revisão de permissões e observabilidade.**
