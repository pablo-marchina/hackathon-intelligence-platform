# W6 — Iteração 9: limites ASGI e prontidão de implantação

**Data:** 2026-10-15
**Base:** Iteração 8 (218 testes locais aprovados).

## Implementado

1. Novo `RequestBodyLimitMiddleware` em nível ASGI. O limite existente
   `MAX_REQUEST_BODY_BYTES` (padrão: 1 MiB) passa a conferir **bytes reais** de
   uploads HTTP mesmo sem `Content-Length`, com `Transfer-Encoding: chunked`,
   com vários frames ASGI ou com tamanho declarado falsamente baixo. Acima do
   limite retorna HTTP 413 antes de executar endpoints/transações. Comprimentos
   inválidos/duplicados geram HTTP 400. O limite é aplicado de forma incremental,
   armazenando no máximo os bytes autorizados; corpos aceitos são repassados
   integralmente ao aplicativo sem perda de conteúdo.
2. Ordem explícita de middlewares: contexto/headers de segurança → validação de
   hostname → CORS → limite de corpo → roteamento. Host inválido recebe 400 sem
   consumir o corpo; um 413 para a origem confiável mantém os headers CORS.
3. Nova rota pública de prontidão `GET /ready`: consulta `alembic_version`
   em PostgreSQL e exige a revisão `0007_w6_source_operations`. Responde
   `200 {"status":"ready"}` somente com DB disponível e atualizado; caso
   contrário `503 {"detail":"service not ready"}` sem revelar host/DSN/SQL.
   `GET /health` continua sendo **liveness**: não depende do banco.
4. Limite de 3 s para conexão PostgreSQL e espera do pool da API, evitando
   probes de prontidão bloqueados por um longo tempo em situações comuns
   de indisponibilidade. O limite final também depende das condições de rede.
5. Adicionado check opt-in `scripts/ops/api_readiness_integration_check.py`
   no job `database-migrations`, **após** a migração Alembic, exigindo
   `APP_ENV=test`, `HIP_ALLOW_SOURCE_DB_DRILL=1` e banco local descartável.
   Esse probe não escreve dados no banco.
6. Testes de upload com frames segmentados, corpo falso/sem Content-Length,
   fronteira exata do limite, host inválido, CORS, esquema desatualizado e
   erro SQL sanitizado. Teste verifica que a revisão esperada coincide com
   o *head* Alembic.

## Comandos de reprodução

```bash
python -m pip install -e '.[dev]'
pytest -q
python scripts/check_eval_gates.py
python scripts/verify_repository.py
```

Em CI isolado com PostgreSQL migrado (apenas para o job existente):

```bash
export APP_ENV=test HIP_ALLOW_SOURCE_DB_DRILL=1
export DATABASE_URL='postgresql+psycopg://hackathon:hackathon@127.0.0.1:5432/hackathon'
python scripts/ops/api_readiness_integration_check.py
```

**Não interpretar** a simples existência do check de CI como evidência de sua
execução. O teste local da rota usa conexões simuladas para indisponibilidade
ou migração incorreta e testa o middleware HTTP real via FastAPI TestClient.
