# Iteração 17 — Cobertura verificável e ponte de atributos estruturados

**Data:** 2026-10-19

**Base:** Iteração 16.

**Status:** implementação local; sem aprovação de produção.
**Foco do roadmap:** MET-01 (parcial), MET-02 (parcial), DATA-02/03 (ponte no W2 histórico), OPS-03 (drill de cobertura no CI). OPS-01 (sincronizar no GitHub) ainda depende de publicação.

## Entregas implementadas

1. `CoverageRepository.snapshot`: consultas somente-leitura ao **banco atual**, distinguindo total de canônicos ativos, próximos/andamento por datas, janela de inscrição comprovada, prazo desconhecido, atributos completos, fontes cadastradas, fontes ativas+aprovadas e fontes com sucesso de coleta recente. Dedup global via `hackathons` sem somar atribuições por fonte. Fonte pode ter múltiplas referências e não significa evento único global.
2. `GET /admin/coverage`: exige autenticação administrativa (perfil VIEWER permitido para leitura), sem exposição de credenciais; painel `/admin` mostra snapshot e atribuições por fonte.
3. `scripts/catalog_coverage_report.py --format json|markdown`: snapshot do PostgreSQL, sem fallback de 250 eventos históricos. Falha explicitamente se não houver conexão.
4. `scripts/ops/catalog_coverage_integration_check.py`: teste com eventos/fontes temporários e **rollback da transação**, opt-in e `APP_ENV=test`, integrado ao CI após aplicar migrações. Testa contagem global distinta e atribuição sobreposta. **Não executado localmente por falta de PostgreSQL.**
5. `structured_projection.py`: converte metadados JSON-LD já extraídos em observações tipadas, com origem, método, normalização estrita e valor bruto preservado. Campos desconhecidos permanecem desconhecidos. Prazo de oferta (`validThrough`) **não é** prazo confirmado de inscrição. Relações de organizadores/patrocinadores continuam como evidência, não como entidades normalizadas.
6. `scripts/run_w2_live.py`: a **rotina histórica W2**, restrita às quatro fontes originais, passa a gravar observações JSON-LD adicionais, seleções e colunas canônicas suportadas (descrição, URL de registro, is_free, participation_fee/moeda); acompanha testes com Gate simulado. **Não** equivale a uma integração operacional generalizada de novas fontes, nem altera controles de permissão.

## Como validar

```bash
python -m pytest -q
python scripts/verify_repository.py
python scripts/check_eval_gates.py
python scripts/source_coverage_report.py --format json
# Requer DATABASE_URL apontando para PostgreSQL real, migrado:
python scripts/catalog_coverage_report.py --format json
# Somente em Postgres de teste descartável, após migrações:
APP_ENV=test HIP_ALLOW_COVERAGE_DB_DRILL=1 python -m scripts.ops.catalog_coverage_integration_check
```

## Limitações e próximos passos obrigatórios

- Falta o teste com PostgreSQL real no CI e a confirmação do build Next.js (sem lockfile npm no checkpoint; não presumir resultado de `npm ci`).
- A captura contínua de novas fontes não se generalizou: o W2 replay mantém uma allowlist estática de quatro fontes. Precisamos ligar parser → observações → reconciliador real sem o gate histórico.
- Organizadores, patrocinadores, idiomas, capacidades e outros dados ricos são observações, mas ainda não são todas relações/taxonomias de busca nem índices persistidos.
- Não houve coleta externa nova nem medição live contra DB neste ambiente. Os 250 eventos W2 permanecem **históricos**, nunca apresentados como total atual.
- A nova iteração foi desenvolvida sobre o ZIP 16, mas não foi enviada automaticamente ao GitHub; uma branch/PR e revisão devem preceder merge, sem sobrescrever `main`.
