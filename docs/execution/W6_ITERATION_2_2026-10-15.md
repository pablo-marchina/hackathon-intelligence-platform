## Entregue

### 1. Painel de operações (`/admin`)

- Nova página Next.js em `apps/web/app/admin/page.tsx`, componente cliente `AdminDashboard.tsx` e navegação **Operations**.
- Fontes: saúde, prioridade, última execução/erro, estado ativo, pausa/retomada.
- Revisões: fila aberta, severidade/evidências e transições **In review**, **Resolved** e **Dismissed**.
- Qualidade: snapshots mais recentes. Auditoria: ações, motivo, ator, entidade, horário.
- Permissões: `VIEWER` apenas lê; `OPERATOR` altera fontes/revisões; `ADMIN` também pode reindexar.
- Campo de justificativa obrigatório (mínimo 8 caracteres, máximo 500) e feedback de erro/sucesso. Ações atualizam os dados em seguida.
- Nenhuma chave administrativa em código cliente. `fetch` usa `credentials: 'include'`, com sessão HttpOnly, e cabeçalho `X-CSRF-Token` nas mutações.
- `GET /admin/me` faz o bootstrap do papel da sessão e entrega o valor do cookie CSRF **apenas para sessão autenticada**. A resposta tem `Cache-Control: no-store`; chave de serviço recebe papel `ADMIN`, mas **não** recebe token CSRF. As outras rotas continuam exigindo RBAC/CSRF no backend.

**Configuração obrigatória para funcionar em navegador:**

1. Usuário deve autenticar e receber `hip_session` e `hip_csrf` do backend. Administrador atribui papel explicitamente em `admin_user_roles`, sem autoelevação por domínio/email.
2. `NEXT_PUBLIC_API_URL` deve apontar para a API acessível a partir do navegador; `CORS_ORIGINS` deve conter **exatamente** a origem do frontend, nunca `*` com credenciais.
3. Web e API devem compartilhar um **site** (por exemplo, `www.example.com` e `api.example.com` sob HTTPS) ou um reverse proxy same-origin. Cookies estão `SameSite=Lax`: se os hosts forem *cross-site* não há suporte a browser admin sem redesenhar a política de cookies/autenticação. Localmente `localhost:3000` e `localhost:8000` compartilham o mesmo site.
4. A variável `ADMIN_API_KEY` é segredo backend e **não** deve ser prefixada com `NEXT_PUBLIC_` nem copiada para `apps/web`.

Exemplo local:

```bash
# Serviços de PostgreSQL / Redis / API precisam estar ativos e migração 0006 aplicada.
cd apps/web && npm install --no-audit --no-fund && NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
# Autenticar pela barra superior, depois acessar http://localhost:3000/admin
```

### 2. Pausa de fontes em todos os entrypoints conhecidos

- Novo módulo `hackathon_sources.source_switch` lê o `sources.active` autoritativo pelo par `(domain, source_family)`, em **nova conexão a cada verificação**. Fontes ausentes/desligadas = false; erro de conexão propaga (falha fechada).
- `run_source_once()` e `run_source_rest_gate()` aceitam `is_active` e o consultam **antes** de `discover()`/criar `crawl_run` e novamente antes de cada página. Interrupção intermediária retorna `CANCELLED`; início pausado causa `SourcePausedError`.
- `scripts/run_live_sources.py`: no modo SQL persistido, mantém o verificador anterior; `--no-persist` e REST usam a mesma chave PostgreSQL quando `DATABASE_URL` existe. Para usar REST **com** `DATABASE_URL` (que normalmente daria prioridade a SQL), selecionar `--prefer-rest`. Sem `DATABASE_URL`, execução não persistida/REST é negada, a menos que se solicite **explicitamente** `--allow-unmanaged-fetch`, apenas em `APP_ENV=development|test`.
- `api/live_sources.py`: requisições devem fornecer `X-Gate-Token: <LIVE_SOURCES_GATE_TOKEN>` com o segredo configurado; sem segredo, retorna 503. O endpoint consulta o PostgreSQL quando disponível. Sem ele, só permite fetch com `LIVE_SOURCES_ALLOW_UNMANAGED_FETCH=1` em `development|test`. Erros internos não retornam stack traces ou detalhes de exceção.
- O bloqueio cobre os **entrypoints de coleta SDK/CLI e o endpoint diagnóstico**; o script legado **`scripts/run_w3_live_gate.py`** faz descoberta web independente com `urllib`, sem o switch `sources.active` (continua fora do escopo e não deve ser usado como worker operacional). Integrações externas que chamem diretamente `run_source_once` ou `run_source_rest_gate` ainda precisam passar `is_active` e aplicar a mesma política. Uma chamada HTTP já iniciada pode concluir após a pausa, mas não é iniciada uma nova página com o estado desativado.

**Comandos de diagnóstico:**

```bash
# Recomendado: banco com sources registradas / migrações aplicadas
DATABASE_URL='postgresql+psycopg://...' python scripts/run_live_sources.py --no-persist --source hackclub_hackathons

# REST persistido mantendo verificação PostgreSQL (credenciais REST também necessárias)
DATABASE_URL='postgresql+psycopg://...' GATE_WRITE_URL='https://...' GATE_TOKEN='...' \
  python scripts/run_live_sources.py --prefer-rest --source hackclub_hackathons

# Apenas teste isolado, SEM switch central; nunca em staging/production
APP_ENV=test python scripts/run_live_sources.py --no-persist --allow-unmanaged-fetch --source hackclub_hackathons
```

Não configure `LIVE_SOURCES_ALLOW_UNMANAGED_FETCH=1` em produção, mesmo com autenticação.
