# W6 — Iteração 8: leases com relógio do banco e integração multiworker

**Data:** 15/10/2026. **Base:** Iteração 7, com 205 testes aprovados localmente.
**Resultado desta iteração:** 218 testes locais aprovados, avaliações versionadas PASS e
verificação estática de 74 tabelas/5 extensões PASS. **Nenhum serviço PostgreSQL,
Redis ou Celery real foi iniciado neste ambiente**; execução externa do CI continua pendente.

## Escopo implementado

1. `claim_due_source`, `renew_lease` e `complete_lease` agora leem o tempo diretamente de
   `clock_timestamp()` dentro da instrução SQL, em uma CTE `MATERIALIZED` compartilhada.
   O token, a expiração e a próxima janela de coleta são julgados pelo **mesmo relógio do
   banco**, não pelo relógio de cada host. A injeção `now=` foi mantida **somente** para
   testes determinísticos e não é utilizada pelo dispatcher/heartbeat em produção.
2. A cláusula `FOR UPDATE ... SKIP LOCKED` continua presente para evitar claims duplicados
   quando dois workers competem por um mesmo item. O fencing por token e o bloqueio de
   sources pausadas/restritas continuam obrigatórios.
3. Novo `scripts/ops/source_multiworker_integration_check.py`: usa duas conexões e
   threads concorrentes em um banco PostgreSQL migrado e isolado. Valida um único claim,
   TTL definido a partir do relógio do banco, renovação válida, expiração sem ressurreição,
   rejeição de token antigo e pausa administrativa. Não dispara HTTP.
4. Novo `scripts/ops/celery_redis_integration_check.py`: despacha somente a tarefa inerte
   `system.ping` na fila `hip-ci-smoke`, verifica o resultado `pong` de um worker real
   e apaga o resultado do backend. O scheduler permanece desligado.
5. CI: `database-migrations` executa o drill multiworker após migrar; novo job
   `celery-redis-integration` sobe Redis e um worker isolado em `pool=solo` para comprovar
   transporte real por Redis. Ambos só aceitam ambiente de teste opt-in.

## Reproduzir em CI ou staging isolado

O workflow `.github/workflows/ci.yml` contém os testes com containers efêmeros.
Para reprodução **somente em um ambiente descartável**, com schema migrado:

```bash
# PostgreSQL: NÃO executar num banco compartilhado/de produção
export APP_ENV=test HIP_ALLOW_SOURCE_DB_DRILL=1
export DATABASE_URL='postgresql+psycopg://hackathon:hackathon@127.0.0.1:5432/hackathon'
python scripts/ops/source_multiworker_integration_check.py

# Redis separado, somente após iniciar um worker consumindo hip-ci-smoke
export APP_ENV=test HIP_ALLOW_CELERY_DRILL=1 SOURCE_SCHEDULER_ENABLED=false
export CELERY_BROKER_URL=redis://127.0.0.1:6379/13
export CELERY_RESULT_BACKEND=redis://127.0.0.1:6379/14
celery -A hackathon_worker.app:celery_app worker --pool=solo --concurrency=1 --queues=hip-ci-smoke
# em outro terminal com os mesmos exports:
python scripts/ops/celery_redis_integration_check.py
```

Guards: os testes exigem `APP_ENV=test`, opt-in explícito e endpoints loopback.
O drill PostgreSQL exige nome de banco de teste (`hackathon` ou `hip_test`) e proíbe
parâmetros de URL capazes de redirecionar a conexão, bem como overrides `PGHOST`,
`PGHOSTADDR`, `PGSERVICE` e `PGSERVICEFILE`.
O smoke Redis só usa DBs 13/14, porta 6379 e uma fila separada, sem executar
coletas nem enviar alertas. Recursos PostgreSQL isolados são apagados ao terminar.
